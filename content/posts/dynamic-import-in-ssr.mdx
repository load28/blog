## Dynamic Import의 기본 개념

Dynamic Import를 이용하면 비동기적으로 모듈을 불러올 수 있습니다. 이는 초기 번들 크기를 줄이고 필요한 시점에만 코드를 로드하여 성능을 최적화하는 데 효과적입니다.

```ts
const loader = async () => import('[path]');
loader().then((data) => console.log(data));
```

JavaScript ES6부터 Dynamic Import를 네이티브로 지원합니다. 코드에서 유의해야 할 점은 `import()` 문이 Promise를 반환하므로 async/await 또는 then/catch로 처리해야 한다는 점입니다.

## React에서의 Dynamic Import

React에서는 `lazy` 함수와 Dynamic Import 문법을 결합하여 컴포넌트를 별도의 청크 파일로 분리할 수 있습니다.

```tsx
import { lazy, Suspense } from 'react';

const LazyComponent = lazy(() => import('./LazyComponent'));

const WrapComponent = () => {
  return (
    <Suspense fallback={<div>Loading...</div>}>
      <LazyComponent />
    </Suspense>
  );
};
```

> 이 글은 Dynamic Import에 집중하므로 Suspense에 대해서는 별도로 다루지 않습니다.

### 렌더링 흐름

1. 초기 렌더링 완료
2. 아직 `LazyComponent`가 로드되지 않았으므로 `fallback UI`가 표시됨
3. Dynamic Import로 인해 별도의 청크 파일을 요청(HTTP)하고 응답 받음
4. 응답받은 컴포넌트를 하이드레이션하여 컴포넌트를 사용할 준비 완료
5. 로딩 대신 `LazyComponent`를 렌더링함

## Next.js에서의 Dynamic Import

Next.js에서도 `lazy` 함수와 `Suspense`를 이용해 Dynamic Import를 사용할 수 있습니다. 그러나 서버 컴포넌트에서는 기존의 방식대로 적용이 불가능합니다.

### 서버 컴포넌트의 제약

`lazy` 함수는 클라이언트 컴포넌트에서만 사용할 수 있습니다. 서버 컴포넌트에서 사용하기 위해서는 클라이언트 컴포넌트로 한번 감싸서 사용해야 합니다.

```tsx
// ClientLazyComponent.tsx
'use client';
import { lazy, Suspense } from 'react';

const LazyComponent = lazy(() => import('./LazyComponent'));

export const ClientComponent = () => {
  return (
    <Suspense fallback={<div>Loading...</div>}>
      <LazyComponent />
    </Suspense>
  );
};

// ServerComponent.tsx
export default function ServerPage() {
  return (
    <div>
      <ClientComponent />
    </div>
  );
}
```

### Next.js Dynamic 함수

서버 컴포넌트에서 Dynamic Import를 직접 선언할 수 없다는 불편함을 해결하기 위해, Next.js는 `dynamic` 함수를 제공합니다.

```tsx
import dynamic from 'next/dynamic';

const LazyComponent = dynamic(() => import('[path]'), {
  ssr: true,
  loading: () => <div>Loading...</div>
});

export default function ServerPage() {
  return (
    <LazyComponent />
  );
}
```

이 함수의 특징은 서버/클라이언트 컴포넌트에서 모두 사용할 수 있으며, 별도의 `Suspense` 선언 없이도 로딩 UI를 표시할 수 있다는 것입니다.

## Lazy vs Dynamic 비교

두 가지 방법으로 Dynamic Import가 모두 가능한 경우, 어떤 것을 선택해야 하는지 비교해봅시다.

### Dynamic 함수의 장점

- 서버와 클라이언트 컴포넌트 모두에서 사용 가능
- `ssr` 옵션을 통해 서버 사이드 렌더링 여부 제어 가능
- 별도의 `Suspense` 없이도 loading UI 표시 가능
- Next.js에 최적화된 API

### Lazy 함수의 특징

- React의 표준 API
- 클라이언트 컴포넌트에서만 사용 가능
- `Suspense`와 함께 사용해야 함
- 어떤 컴포넌트를 사용하든 별도의 청크 파일을 요청하는 방식으로 동작

## SSR 제어의 핵심 차이점

가장 큰 차이점은 **SSR을 제외할 수 있는지 여부**입니다.

### Lazy 함수의 SSR 동작

`lazy` 함수를 통해 Dynamic Import하거나 `Suspense`로 감싸서 로딩을 표시한다고 해도, 최상위 컴포넌트가 서버 컴포넌트인 경우 SSR에 포함됩니다.

```tsx
// 이 경우에도 LazyComponent는 SSR에 포함됨
export default function ServerPage() {
  return (
    <ClientComponent> {/* 내부에서 lazy 사용 */}
      <LazyComponent />
    </ClientComponent>
  );
}
```

### Dynamic 함수의 SSR 제어

`dynamic` 함수를 사용하면 `ssr: false` 옵션으로 SSR을 명시적으로 제외할 수 있습니다. SSR에서 제외한다는 것은 초기 HTML에 빈자리로 표시하고 클라이언트에서 온전히 대체함을 의미합니다.

```tsx
const ClientOnlyComponent = dynamic(() => import('./HeavyComponent'), {
  ssr: false,
  loading: () => <div>Loading...</div>
});
```

이는 다음과 같은 경우에 유용합니다:

- 브라우저 API에 의존하는 컴포넌트 (window, document 등)
- 매우 무거운 차트 라이브러리
- 초기 렌더링에 필수적이지 않은 기능

## 선택 가이드

### Dynamic 함수를 사용해야 하는 경우

- Next.js 프로젝트에서 서버 컴포넌트를 사용하는 경우
- SSR을 선택적으로 제어해야 하는 경우
- 간편한 로딩 UI 설정이 필요한 경우

### Lazy 함수를 사용해야 하는 경우

- React 표준 API만으로 구현하고 싶은 경우
- 클라이언트 컴포넌트에서만 사용하는 경우
- Next.js가 아닌 순수 React 애플리케이션

## 결론

Next.js 환경에서는 `dynamic` 함수가 서버/클라이언트 컴포넌트 간의 경계를 넘나들며 유연하게 코드 스플리팅을 적용할 수 있는 최적의 솔루션입니다. 특히 SSR 제어가 필요한 경우 `dynamic` 함수의 `ssr` 옵션을 활용하면 효과적입니다.

하지만 React 표준 API인 `lazy`도 충분히 강력하므로, 프로젝트의 특성과 요구사항에 따라 적절한 방법을 선택하는 것이 중요합니다.
