Next.js에서 로그인 시스템을 개발할 때, 가장 효율적인 방법 중 하나는 Google과 같은 서드파티 플랫폼을 이용하여 계정을 연동하는 것입니다. 저는 Next.js의 공식 인증 라이브러리인 **Auth.js**(이전 명칭: next-auth)를 사용하여 이를 구현했습니다.

이 글에서는 Auth.js의 아키텍처 이해, DynamoDB를 활용한 세션 저장소 설계, 보호된 라우트 구현, 그리고 실제 프로덕션 환경에서 고려해야 할 보안 및 성능 최적화 방법을 다룹니다.

## Auth.js 선택 근거

### 인증 라이브러리 비교

| 라이브러리 | 장점 | 단점 | 사용 사례 |
|-----------|------|------|-----------|
| **Auth.js** | Next.js 최적화, 다양한 Provider 지원, DB 어댑터 풍부 | 커스터마이징 제한적 | 빠른 MVP, 표준 OAuth 흐름 |
| **Clerk** | 아름다운 UI, 관리 대시보드 | 유료, Vendor Lock-in | SaaS 제품, B2C 앱 |
| **Supabase Auth** | 백엔드 포함, 실시간 기능 | Supabase 종속 | Supabase 사용 프로젝트 |
| **직접 구현** | 완전한 제어 | 보안 위험, 개발 시간 | 특수 요구사항, 레거시 시스템 |

**Auth.js를 선택한 이유:**
1. Next.js App Router와의 완벽한 통합
2. DynamoDB 어댑터 공식 지원
3. 무료 오픈소스 (비용 절감)
4. Google/GitHub/Email 등 다양한 Provider

## 인증 시스템 아키텍처

### 전체 흐름도

```
┌─────────────┐
│   사용자    │
└──────┬──────┘
       │ 1. "Sign in with Google" 클릭
       ▼
┌─────────────────────────────────┐
│  /api/auth/signin/google        │  (Auth.js 제공)
└──────┬──────────────────────────┘
       │ 2. Google OAuth 페이지로 리다이렉트
       ▼
┌─────────────────────────────────┐
│   Google Login Page             │
└──────┬──────────────────────────┘
       │ 3. 사용자 인증 및 동의
       ▼
┌─────────────────────────────────┐
│  /api/auth/callback/google      │  (Auth.js 처리)
│  - 사용자 정보 받기             │
│  - DynamoDB에 User/Session 저장 │
└──────┬──────────────────────────┘
       │ 4. baseUrl로 리다이렉트
       ▼
┌─────────────────────────────────┐
│   /main (보호된 페이지)          │
│   - Middleware가 세션 확인      │
│   - 세션 있으면 접근 허용       │
└─────────────────────────────────┘
```

### 핵심 구성 요소

1. **Auth.js 설정 파일** (`auth.config.ts`, `auth.ts`)
2. **API 라우트 핸들러** (`api/auth/[...nextauth]/route.ts`)
3. **Middleware** (보호된 라우트 체크)
4. **SessionProvider** (클라이언트 세션 접근)

## 로그인 구현 시 주요 고려사항

로그인 기능을 구현할 때는 다음 세 가지 주요 측면을 고려해야 합니다:

1. 로그인 프로세스
2. 로그인 후 세션 획득
3. 보호된 라우트에 대한 세션 확인

각 요구사항의 구현 방법을 살펴보겠습니다.

## 1. 로그인 설정

로그인 설정을 위해 auth.config.ts와 auth.ts 두 파일을 생성해야 합니다.

```typescript
// auth.config.ts
import { NextAuthConfig } from 'next-auth';
import Google from 'next-auth/providers/google';
import { DynamoDBAdapter } from '@auth/dynamodb-adapter';
import { DynamoDB } from '@aws-sdk/client-dynamodb';
import { DynamoDBDocument } from '@aws-sdk/lib-dynamodb';
import type { DynamoDBClientConfig } from '@aws-sdk/client-dynamodb';

// DynamoDB 클라이언트 설정
const config: DynamoDBClientConfig = {
  credentials: {
    accessKeyId: process.env.AUTH_DYNAMODB_ID as string,
    secretAccessKey: process.env.AUTH_DYNAMODB_SECRET as string,
  },
  region: process.env.AUTH_DYNAMODB_REGION,
  endpoint: process.env.AUTH_DYNAMODB_END_POINT, // 로컬 개발용
};

const client = DynamoDBDocument.from(new DynamoDB(config), {
  marshallOptions: {
    convertEmptyValues: true,      // 빈 문자열을 DynamoDB null로 변환
    removeUndefinedValues: true,    // undefined 값 제거
    convertClassInstanceToMap: true, // 클래스 인스턴스를 Map으로 변환
  },
});

export const authConfig = {
  providers: [
    Google({
      clientId: process.env.NEXT_PUBLIC_AUTH_GOOGLE_ID,
      clientSecret: process.env.AUTH_GOOGLE_SECRET,
      // 추가 스코프 (선택)
      authorization: {
        params: {
          scope: 'openid email profile',
          prompt: 'consent', // 매번 동의 화면 표시 (개발용)
        },
      },
    }),
  ],
  session: {
    strategy: 'database', // 'jwt' 또는 'database'
    maxAge: 30 * 24 * 60 * 60, // 30일 (초 단위)
    updateAge: 24 * 60 * 60,    // 24시간마다 세션 업데이트
  },
  callbacks: {
    // 로그인 후 리다이렉트 URL 제어
    async redirect({ url, baseUrl }) {
      // 같은 도메인만 허용 (보안)
      if (url.startsWith(baseUrl)) return url;
      // 상대 경로 허용
      if (url.startsWith('/')) return `${baseUrl}${url}`;
      return baseUrl;
    },
    // 세션에 사용자 ID 추가
    async session({ session, user }) {
      if (session.user) {
        session.user.id = user.id;
      }
      return session;
    },
  },
  adapter: DynamoDBAdapter(client),
  debug: process.env.NODE_ENV === 'development',
  pages: {
    signIn: '/login',  // 커스텀 로그인 페이지
    error: '/auth/error', // 에러 페이지
  },
} satisfies NextAuthConfig;

// auth.ts
import NextAuth from 'next-auth';
import { authConfig } from './auth.config';

export const { auth, handlers, signIn, signOut } = NextAuth(authConfig);
```

**설계 의사결정:**

### Session Strategy: Database vs JWT

| 전략 | 장점 | 단점 | 선택 이유 |
|------|------|------|----------|
| **JWT** | 빠름 (DB 조회 불필요), 서버리스 친화적 | 즉시 무효화 불가, 크기 제한 | - |
| **Database** [권장] | 즉시 로그아웃 가능, 세션 통계 수집 | DB 조회 오버헤드 | Todo 앱은 세션 무효화 필요 |

### DynamoDB marshallOptions

- `convertEmptyValues: true`: 사용자 이름이 비어있을 경우 처리
- `removeUndefinedValues: true`: 선택적 필드 처리

### Session 만료 시간

- `maxAge: 30일`: 사용자 편의성 (다시 로그인 필요 없음)
- `updateAge: 24시간`: 세션 갱신으로 만료 방지

또한 인증을 위한 라우트 핸들러를 생성해야 합니다:

```typescript
// api/auth/[...nextauth]/route.ts
import { handlers } from '@/app/auth';

export const { GET, POST } = handlers;

// 런타임 설정 (선택)
export const runtime = 'nodejs'; // 또는 'edge'
```

**Catch-all 라우트 설명:**

`[...nextauth]`는 다음 경로를 모두 처리합니다:
- `GET /api/auth/signin`: 로그인 페이지
- `POST /api/auth/signin/google`: Google OAuth 시작
- `GET /api/auth/callback/google`: OAuth 콜백
- `POST /api/auth/signout`: 로그아웃
- `GET /api/auth/session`: 세션 정보 조회

이 설정을 통해 Auth.js에서 제공하는 로그인, 로그아웃 및 세션 정보 조회 메서드를 사용할 수 있습니다. auth.config 에 보면 DynamoDBAdapter(client) 부분이 있는데 이것은 유저, 세션 정보를 데이터베이스로 저장 할 때에 어떤 디비를 사용할지 설정하는 부분입니다. auth.js에서는 제가 이 프로젝트의 디비로 사용하고자 하는 DynamoDB에 대한 어탭터로 제공하므로 설정만 하면 자동으로 디비와 연동이 됩니다.

## DynamoDB 테이블 스키마

Auth.js DynamoDB 어댑터는 **3개의 테이블**을 사용합니다:

```typescript
// 테이블 구조 (자동 생성)

// 1. User 테이블
{
  pk: "USER#google-oauth2|123456",  // Primary Key
  sk: "USER#google-oauth2|123456",  // Sort Key
  id: "google-oauth2|123456",
  name: "John Doe",
  email: "john@example.com",
  image: "https://lh3.googleusercontent.com/...",
  emailVerified: null,
  GSI1PK: "USER#john@example.com", // Global Secondary Index
  GSI1SK: "USER#john@example.com"
}

// 2. Session 테이블
{
  pk: "USER#google-oauth2|123456",
  sk: "SESSION#session-token-xyz",
  sessionToken: "session-token-xyz",
  userId: "google-oauth2|123456",
  expires: 1704067200000, // Unix timestamp
  GSI1PK: "SESSION#session-token-xyz",
  GSI1SK: "SESSION#session-token-xyz"
}

// 3. Account 테이블
{
  pk: "USER#google-oauth2|123456",
  sk: "ACCOUNT#google#123456",
  userId: "google-oauth2|123456",
  provider: "google",
  providerAccountId: "123456",
  type: "oauth",
  access_token: "ya29.a0...",
  expires_at: 1704067200,
  id_token: "eyJhbGciOiJSUzI1NiIsImtpZCI6Ij...",
  scope: "openid email profile",
  token_type: "Bearer"
}
```

**로컬 DynamoDB 설정 (개발용):**

```bash
# Docker로 DynamoDB Local 실행
docker run -p 8000:8000 amazon/dynamodb-local

# 테이블 생성 (Auth.js가 자동 생성하지만 수동 생성 가능)
aws dynamodb create-table \
  --table-name next-auth \
  --attribute-definitions \
    AttributeName=pk,AttributeType=S \
    AttributeName=sk,AttributeType=S \
    AttributeName=GSI1PK,AttributeType=S \
    AttributeName=GSI1SK,AttributeType=S \
  --key-schema \
    AttributeName=pk,KeyType=HASH \
    AttributeName=sk,KeyType=RANGE \
  --global-secondary-indexes \
    IndexName=GSI1,KeySchema=[{AttributeName=GSI1PK,KeyType=HASH},{AttributeName=GSI1SK,KeyType=RANGE}],Projection={ProjectionType=ALL},ProvisionedThroughput={ReadCapacityUnits=5,WriteCapacityUnits=5} \
  --provisioned-throughput ReadCapacityUnits=5,WriteCapacityUnits=5 \
  --endpoint-url http://localhost:8000
```

## 2. 세션 획득

세션 정보를 획득하기 위해 애플리케이션의 최상위 레벨에 ClientSessionProvider를 선언해야 합니다.

```typescript
// components/ClientSessionProvider.tsx
'use client';

import { SessionProvider } from 'next-auth/react';
import { PropsWithChildren } from 'react';

export function ClientSessionProvider({ children }: PropsWithChildren) {
  return (
    <SessionProvider
      refetchInterval={5 * 60} // 5분마다 세션 갱신
      refetchOnWindowFocus={true} // 윈도우 포커스 시 갱신
    >
      {children}
    </SessionProvider>
  );
}
```

```typescript
// app/layout.tsx
import { ClientSessionProvider } from '@/components/ClientSessionProvider';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        <ClientSessionProvider>
          {children}
        </ClientSessionProvider>
      </body>
    </html>
  );
}
```

이를 통해 하위 컴포넌트에서 세션 정보에 접근할 수 있습니다.

**refetchInterval 설정 근거:**
- 5분: 세션 만료를 빠르게 감지하면서 과도한 요청 방지
- 실시간성이 중요한 앱은 1분, 그렇지 않으면 10-15분

## 3. 보호된 라우트

보호된 라우트를 처리하기 위해 세션 정보를 확인하고 필요시 리다이렉트하는 미들웨어를 구현할 수 있습니다.

```typescript
// middleware.ts
import { auth } from '@/app/auth';
import { NextResponse } from 'next/server';

// 보호된 경로 패턴
const protectedPaths = ['/main', '/settings', '/profile'];

function isProtectedRoute(pathname: string): boolean {
  return protectedPaths.some(route => pathname.startsWith(route));
}

export default auth((req) => {
  const { pathname } = req.nextUrl;

  if (isProtectedRoute(pathname)) {
    if (!req.auth) {
      // 로그인되지 않음 → 로그인 페이지로 리다이렉트
      const loginUrl = new URL('/login', req.url);
      loginUrl.searchParams.set('callbackUrl', pathname); // 로그인 후 돌아갈 URL
      return NextResponse.redirect(loginUrl);
    }

    // 추가 권한 체크 (선택)
    const userRole = req.auth.user?.role;
    if (pathname.startsWith('/admin') && userRole !== 'admin') {
      return NextResponse.redirect(new URL('/forbidden', req.url));
    }
  }

  return NextResponse.next();
});

// Middleware 적용 경로
export const config = {
  matcher: [
    // 보호된 경로
    '/main/:path*',
    '/settings/:path*',
    '/profile/:path*',
    // API 라우트 제외
    '/((?!api|_next/static|_next/image|favicon.ico).*)',
  ],
};
```

이 미들웨어는 지정된 패턴과 일치하는 라우트에 대해 세션 정보를 확인하고, 세션이 없는 경우 로그인 페이지로 리다이렉트합니다.

**Matcher 최적화:**
- API 라우트(`/api/*`)는 제외하여 성능 향상
- 정적 파일(`_next/static`)도 제외

## 로그인/로그아웃 UI 구현

```typescript
// app/login/page.tsx
import { signIn } from '@/app/auth';

export default function LoginPage({
  searchParams,
}: {
  searchParams: { callbackUrl?: string };
}) {
  async function handleGoogleLogin() {
    'use server';
    await signIn('google', {
      redirectTo: searchParams.callbackUrl || '/main',
    });
  }

  return (
    <div>
      <h1>Sign in to Todo App</h1>
      <form action={handleGoogleLogin}>
        <button type="submit">Sign in with Google</button>
      </form>
    </div>
  );
}
```

```typescript
// components/LogoutButton.tsx
'use client';

import { signOut } from 'next-auth/react';

export function LogoutButton() {
  return (
    <button onClick={() => signOut({ callbackUrl: '/login' })}>
      Sign out
    </button>
  );
}
```

**Server Action vs Client Action:**
- 로그인: Server Action (`'use server'`) - SEO 친화적
- 로그아웃: Client Action - 즉시 피드백 필요

### 2. CSRF 보호

Auth.js는 **자동으로 CSRF 토큰**을 생성하여 보호합니다:

```typescript
// 내부적으로 처리됨
// POST /api/auth/signin/google
{
  csrfToken: 'random-token',
  callbackUrl: '/main'
}
```

### 3. Session Hijacking 방지

```typescript
// auth.config.ts
export const authConfig = {
  // ...
  callbacks: {
    async session({ session, user }) {
      // 세션에 IP 주소 저장 (선택)
      const clientIp = req.headers.get('x-forwarded-for') || req.ip;
      if (session.lastIp && session.lastIp !== clientIp) {
        // IP 변경 감지 → 재인증 요구
        throw new Error('Session invalid: IP mismatch');
      }
      session.lastIp = clientIp;
      return session;
    },
  },
};
```

## UX 고려사항

이러한 기능을 구현하는 과정에서 세션 정보 획득 타이밍과 관련된 UX 문제를 발견했습니다. 서버 컴포넌트는 빠르게 렌더링되지만, ClientSessionProvider는 클라이언트 측에서 세션 정보를 주입하여 타이밍 불일치가 발생합니다.

이 문제는 인증에만 국한된 것이 아니라 Next.js에서 UI 기능을 구현할 때 흔히 발생합니다. 이를 해결하기 위해 다음과 같은 방법을 사용할 수 있습니다:

**서버 컴포넌트에서 데이터를 생성**하고 props나 context를 통해 클라이언트 컴포넌트에 주입합니다. 또는 서버 컴포넌트에서 React Query를 사용하여 프리페칭을 수행하고, 클라이언트 컴포넌트에서 즉시 프리페치된 데이터를 사용합니다.

### 서버 컴포넌트에서 세션 사용

```typescript
// app/main/page.tsx (Server Component)
import { auth } from '@/app/auth';
import { redirect } from 'next/navigation';

export default async function MainPage() {
  const session = await auth();

  if (!session) {
    redirect('/login');
  }

  // 세션을 props로 전달 (추가 요청 방지)
  return <TodoList user={session.user} />;
}
```

**장점:**
- 클라이언트에서 `/api/auth/session` 호출 불필요
- 초기 렌더링 속도 향상

이러한 접근 방식을 통해 더 빠른 UI 렌더링과 더 나은 사용자 경험을 제공할 수 있습니다. 이러한 솔루션을 구현함으로써 Next.js에서 로그인, 세션 관리, 보호된 라우트 처리를 효과적으로 다루는 강력한 인증 시스템을 만들 수 있으며, 동시에 우수한 사용자 경험을 유지할 수 있습니다.

## 프로덕션 배포 고려사항

### Vercel 배포 (권장)

```bash
# 환경 변수 설정
vercel env add AUTH_GOOGLE_SECRET
vercel env add AUTH_SECRET
vercel env add AUTH_DYNAMODB_ID
vercel env add AUTH_DYNAMODB_SECRET

# 배포
vercel --prod
```

### Google OAuth Console 설정

1. **Authorized redirect URIs:**
   ```
   https://todo-app.com/api/auth/callback/google
   http://localhost:3000/api/auth/callback/google  # 개발용
   ```

2. **Authorized JavaScript origins:**
   ```
   https://todo-app.com
   http://localhost:3000
   ```

## 결론

Auth.js와 DynamoDB를 활용한 인증 시스템은 다음 요구사항을 만족했습니다:

1. **보안**: OAuth 2.0, CSRF 보호, Session Hijacking 방지
2. **확장성**: DynamoDB의 무한 확장, Pay-per-request 모델
3. **개발 속도**: Auth.js의 풍부한 기능으로 빠른 구현
4. **비용 효율**: 오픈소스 + AWS Free Tier 활용

특히 **Middleware를 통한 보호된 라우트 구현**은 Next.js의 강력한 기능을 활용한 예시이며, Server Component에서 세션을 직접 가져오는 방식은 클라이언트 요청을 줄여 성능을 크게 향상시켰습니다.

프로덕션 환경에서는 Rate Limiting, 로깅, MFA 등 추가 보안 계층을 구축하여 더욱 견고한 시스템을 만들 수 있습니다.
