Next.js를 이용해 Todo 앱을 개발하는 과정에서 생성 모달과 업데이트 모달을 어떻게 설계하고 구현했는지, 그리고 코드의 확장성을 어떻게 확보할 수 있었는지에 대해 다룹니다. 이 글은 **실제 프로젝트에서 직면한 설계 문제와 해결 과정**을 중심으로, 재사용 가능한 컴포넌트 패턴과 상태 관리 전략을 설명합니다.

## 프로젝트 개요

### 핵심 기능

Todo 앱은 **날짜별로 Todo를 관리**하는 웹 애플리케이션입니다. 주요 기능은:

1. **날짜 선택**: 달력에서 날짜를 선택하면 해당 날짜의 Todo 목록 표시
2. **Todo 생성**: 선택한 날짜에 새로운 Todo 추가 (기본 4개 슬롯)
3. **Todo 수정**: 기존 Todo 내용 변경
4. **날짜 이동**: 모달 내에서 다른 날짜로 전환 시 자동으로 생성/수정 모드 전환

### 기술 스택 선택 근거

| 기술 | 선택 이유 |
|------|-----------|
| **Next.js 14** | App Router의 서버 컴포넌트를 활용한 초기 데이터 로딩 최적화 |
| **React Query** | 날짜별 Todo 캐싱 및 Optimistic Update 구현 |
| **Mantine UI** | 접근성이 보장된 Modal, DatePicker 컴포넌트 제공 |
| **Context API** | 모달 간 날짜 상태 공유 (Redux 대비 간단한 상태 구조) |
| **TypeScript** | 타입 안전성 확보 (특히 날짜 포맷 관련 오류 방지) |

## 핵심 설계 과제

### 문제 상황: 생성 vs 수정 모달의 이중성

초기 요구사항을 분석하면서 발견한 핵심 과제는 **하나의 UI를 두 가지 모드로 사용**해야 한다는 점이었습니다:

```
┌─────────────────────────────────────┐
│  사용자가 날짜를 선택               │
└───────────┬─────────────────────────┘
            │
            ▼
     해당 날짜에 Todo가 있는가?
            │
      ┌─────┴─────┐
      │           │
     있음        없음
      │           │
      ▼           ▼
  수정 모달    생성 모달
  (기존 데이터)  (빈 슬롯 4개)
```

**설계 선택지:**

1. **단일 컴포넌트 + 조건부 렌더링**
   - 장점: 코드 중복 없음
   - 단점: 복잡한 조건문, 생성/수정 로직 혼재

2. **별도 컴포넌트 + 공통 UI 추출** ✅
   - 장점: 각 모드의 책임 명확, 테스트 용이
   - 단점: 약간의 보일러플레이트 코드

두 번째 접근을 선택한 이유:
- 생성 모달에만 필요한 기능 추가 시 수정 모달에 영향 없음
- 각 모달의 비즈니스 로직이 독립적으로 발전 가능

## 아키텍처 구현

### 1. 상위 컨테이너: SaveTodoModal

```typescript
// components/SaveTodoModal.tsx
export function SaveTodoModal({ date }: PropsWithoutRef<{ date: string }>) {
  const tzCtx = useTzContext();
  const [cachedDate, setCachedDate] = useState<Date | null>(
    dayjs(date).toDate()
  );

  // React Query로 전체 Todo 맵 가져오기
  const { data: todoMap } = useQuery({
    queryKey: ["todos"],
    queryFn: getTodos(tzCtx?.tz),
  });

  // 현재 선택된 날짜의 Todo 추출
  const todos = useMemo(
    () =>
      todoMap?.[dayjs(cachedDate).format("YYYY-MM-DD")]?.map(
        (todo) => todo.description
      ),
    [todoMap, cachedDate]
  );

  return (
    <SaveTodoDataProvider
      value={{ date: cachedDate, setDate: setCachedDate }}
    >
      {todos ? <EditTodoModal todos={todos} /> : <CreateTodoModal />}
    </SaveTodoDataProvider>
  );
}
```

**설계 의사결정:**

1. **날짜 캐싱 (cachedDate)**
   - 모달 내에서 날짜를 변경해도 부모 컴포넌트에 즉시 반영하지 않음
   - "Save" 버튼 클릭 시에만 실제 데이터 저장
   - 사용자가 실수로 날짜를 변경해도 "Cancel"로 되돌릴 수 있음

2. **Context로 날짜 상태 공유**
   - Props Drilling 방지
   - SaveTodo.Date 컴포넌트가 여러 곳에서 재사용 가능

3. **조건부 컴포넌트 렌더링**
   - `todos` 존재 여부로 Edit/Create 결정
   - 빈 배열(`[]`)도 "수정 모드"로 간주 (의도적 설계)

### 2. Context 설계

```typescript
// context/SaveTodoDataContext.tsx
type SaveTodoDataContextType = {
  date: Date | null;
  setDate: (date: Date | null) => void;
};

const SaveTodoDataContext = createContext<SaveTodoDataContextType | null>(null);

export const SaveTodoDataProvider = SaveTodoDataContext.Provider;

export function useSaveTodoDataContext() {
  const context = useContext(SaveTodoDataContext);
  if (!context) {
    throw new Error(
      'useSaveTodoDataContext must be used within SaveTodoDataProvider'
    );
  }
  return context;
}
```

**에러 처리 전략:**
- Context가 없는 곳에서 hook 사용 시 명확한 에러 메시지
- 개발 중 실수를 빠르게 발견 가능

### 3. 생성 모달 구현

```typescript
// components/CreateTodoModal.tsx
export const CreateTodoModal = () => {
  const ctx = useSaveTodoDataContext();
  const modalCtx = useModalControlContext();
  const [todos, setTodos] = useState<string[]>(
    Array.from({ length: 4 }, () => "")
  );
  const queryClient = useQueryClient();
  const tzCtx = useTzContext();

  // 생성 Mutation
  const createMutation = useMutation({
    mutationFn: async (data: { date: string; todos: string[] }) => {
      return await fetch('/api/todos', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(data),
      });
    },
    onSuccess: () => {
      // 캐시 무효화로 최신 데이터 다시 가져오기
      queryClient.invalidateQueries({ queryKey: ['todos'] });
      modalCtx?.close();
    },
  });

  const handleSubmit = () => {
    const filteredTodos = todos.filter(todo => todo.trim() !== '');
    if (filteredTodos.length === 0) return;

    createMutation.mutate({
      date: dayjs(ctx.date).format('YYYY-MM-DD'),
      todos: filteredTodos,
    });
  };

  return (
    <Modal
      opened={modalCtx?.opened || false}
      onClose={() => modalCtx?.close()}
      title="Create todo"
      styles={{
        title: {
          fontWeight: 700,
        },
      }}
    >
      <Stack pt={"md"} pb={"md"} pl={"sm"} pr={"sm"} gap={"xl"}>
        <Stack gap={"xl"}>
          <SaveTodo.Date date={ctx.date} setDate={ctx.setDate} />
          <SaveTodo.Todos todos={todos} setTodos={setTodos} />
        </Stack>
        <Button
          mt={"md"}
          color="blue.5"
          onClick={handleSubmit}
          loading={createMutation.isPending}
        >
          Add
        </Button>
      </Stack>
    </Modal>
  );
};
```

**핵심 구현 포인트:**

1. **빈 Todo 필터링**
   - 사용자가 4개 슬롯을 모두 채우지 않아도 저장 가능
   - 공백만 있는 항목은 제외

2. **React Query Mutation**
   - `onSuccess`에서 캐시 무효화로 UI 자동 업데이트
   - `isPending` 상태로 버튼 로딩 표시

3. **공통 컴포넌트 사용**
   - `SaveTodo.Date`, `SaveTodo.Todos`는 수정 모달과 공유

### 4. 수정 모달 구현

```typescript
// components/EditTodoModal.tsx
export function EditTodoModal({ todos }: PropsWithoutRef<{ todos: string[] }>) {
  const ctx = useSaveTodoDataContext();
  const modalCtx = useModalControlContext();
  const [cacheTodos, setCacheTodos] = useState<string[]>(todos);
  const queryClient = useQueryClient();

  // todos prop 변경 시 cacheTodos 동기화
  useEffect(() => {
    setCacheTodos(todos);
  }, [todos]);

  // 수정 Mutation
  const updateMutation = useMutation({
    mutationFn: async (data: { date: string; todos: string[] }) => {
      return await fetch('/api/todos', {
        method: 'PUT',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(data),
      });
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['todos'] });
      modalCtx?.close();
    },
  });

  const handleSubmit = () => {
    const filteredTodos = cacheTodos.filter(todo => todo.trim() !== '');

    updateMutation.mutate({
      date: dayjs(ctx.date).format('YYYY-MM-DD'),
      todos: filteredTodos,
    });
  };

  return (
    <Modal
      opened={modalCtx?.opened || false}
      onClose={() => modalCtx?.close()}
      title="Edit todo"
      styles={{
        title: {
          fontWeight: 700,
        },
      }}
    >
      <Stack pt={"md"} pb={"md"} pl={"sm"} pr={"sm"} gap={"xl"}>
        <Stack gap={"xl"}>
          <SaveTodo.Date date={ctx.date} setDate={ctx.setDate} />
          <SaveTodo.Todos todos={cacheTodos} setTodos={setCacheTodos} />
        </Stack>
        <Button
          mt={"md"}
          color="blue.5"
          onClick={handleSubmit}
          loading={updateMutation.isPending}
        >
          Edit
        </Button>
      </Stack>
    </Modal>
  );
}
```

**생성 모달과의 차이점:**

1. **Props로 초기 데이터 받음**
   - `todos` prop을 `cacheTodos` 상태로 복사
   - 모달 내 수정이 원본 데이터에 즉시 반영되지 않음

2. **useEffect로 동기화**
   - 모달 내에서 날짜 변경 시 새로운 `todos`가 전달됨
   - `cacheTodos`를 업데이트하여 UI 갱신

3. **PUT 요청 사용**
   - RESTful API 설계 원칙 준수

  setTodos

        <Group key={index} align="flex-start">
          <TextInput
            value={todo}
            onChange={(e) => handleChange(index, e.target.value)}
            placeholder={`Todo ${index + 1}`}
            style={{ flex: 1 }}
          />
          <ActionIcon
            color="red"
            onClick={() => handleRemove(index)}
            disabled={todos.length === 1}
          >
            <IconTrash size={18} />
          </ActionIcon>
        </Group>
      ))}
      <Button variant="light" onClick={handleAdd} leftIcon={<IconPlus size={18} />}>
        Add Todo
      </Button>
    </Stack>
  );
}

### 사례 2: Optimistic Update 구현

**요구사항:** Todo 저장 시 즉시 UI에 반영하고, 실패 시 되돌림

```typescript
// components/CreateTodoModal.tsx (개선)
const createMutation = useMutation({
  mutationFn: async (data: { date: string; todos: string[] }) => {
    return await fetch('/api/todos', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(data),
    }).then(res => {
      if (!res.ok) throw new Error('Failed to create todos');
      return res.json();
    });
  },
  onMutate: async (newData) => {
    // 이전 쿼리 취소
    await queryClient.cancelQueries({ queryKey: ['todos'] });

    // 현재 데이터 백업
    const previousTodos = queryClient.getQueryData(['todos']);

    // Optimistic Update
    queryClient.setQueryData(['todos'], (old: any) => {
      return {
        ...old,
        [newData.date]: newData.todos.map(desc => ({ description: desc })),
      };
    });

    return { previousTodos };
  },
  onError: (err, newData, context) => {
    // 에러 발생 시 이전 상태로 복구
    if (context?.previousTodos) {
      queryClient.setQueryData(['todos'], context.previousTodos);
    }
    console.error('Failed to create todos:', err);
  },
  onSettled: () => {
    queryClient.invalidateQueries({ queryKey: ['todos'] });
  },
});
```

**UX 개선 효과:**
- 네트워크 왕복 시간 없이 즉시 UI 반영
- 사용자는 저장이 완료된 것처럼 느낌
- 실패 시에도 안전하게 원복

### 사례 3: 날짜 변경 시 Unsaved Changes 경고

**요구사항:** 사용자가 Todo를 수정한 후 날짜를 변경하려 하면 경고 표시

```typescript
// components/EditTodoModal.tsx (개선)
export function EditTodoModal({ todos }: PropsWithoutRef<{ todos: string[] }>) {
  const ctx = useSaveTodoDataContext();
  const [cacheTodos, setCacheTodos] = useState<string[]>(todos);
  const [hasUnsavedChanges, setHasUnsavedChanges] = useState(false);

  // todos 변경 감지
  useEffect(() => {
    const isChanged = JSON.stringify(todos) !== JSON.stringify(cacheTodos);
    setHasUnsavedChanges(isChanged);
  }, [todos, cacheTodos]);

  // 날짜 변경 시 경고
  const handleDateChange = (newDate: Date | null) => {
    if (hasUnsavedChanges) {
      if (!confirm('You have unsaved changes. Discard them?')) {
        return;
      }
    }
    ctx.setDate(newDate);
  };

  return (
    <Modal>
      <Stack>
        <SaveTodo.Date date={ctx.date} setDate={handleDateChange} /> {/* 수정 */}
        {/* ... */}
      </Stack>
    </Modal>
  );
}
```

## 직면한 문제와 해결

### 문제 1: 날짜 변경 시 모달 깜빡임

**증상:**
- 모달 내에서 날짜를 변경하면 컴포넌트가 언마운트 후 재마운트됨
- 사용자가 입력하던 내용이 초기화됨

**원인:**
```typescript
// 잘못된 구조
{todos ? <EditTodoModal todos={todos} /> : <CreateTodoModal />}
// todos가 변경되면 완전히 다른 컴포넌트로 교체됨
```

**해결:**
```typescript
// SaveTodoModal 내부에서 날짜 상태 캐싱
const [cachedDate, setCachedDate] = useState<Date | null>(dayjs(date).toDate());

// 모달 내부의 날짜 변경은 cachedDate만 업데이트
// 실제 저장 시에만 부모에게 전파
```

### 문제 2: Context Re-rendering 최적화

**증상:**
- 날짜 변경 시 모든 하위 컴포넌트가 리렌더링됨

**해결:**
```typescript
// Context를 두 개로 분리
const SaveTodoDateContext = createContext<Date | null>(null);
const SaveTodoSetDateContext = createContext<(date: Date | null) => void>(() => {});

// 날짜만 필요한 컴포넌트
function DateDisplay() {
  const date = useContext(SaveTodoDateContext);
  // setDate가 변경되어도 리렌더링 안 됨
}

// setDate만 필요한 컴포넌트
function DatePicker() {
  const setDate = useContext(SaveTodoSetDateContext);
  // date가 변경되어도 리렌더링 안 됨
}
```

### 문제 3: React Query 캐시 동기화

**증상:**
- 다른 탭에서 Todo를 수정해도 현재 탭에 반영 안 됨

**해결:**
```typescript
// queryClient 설정
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5 * 60 * 1000, // 5분
      refetchOnWindowFocus: true, // 탭 전환 시 자동 갱신
      refetchOnReconnect: true,   // 네트워크 재연결 시 갱신
    },
  },
});
```

## 배운 점 및 인사이트

### 1. 컴포넌트 분리의 기준

**잘못된 기준:** "코드 중복이 있으면 무조건 합치자"

**올바른 기준:**
- 비즈니스 로직이 다르면 분리 (생성 vs 수정)
- UI가 같아도 책임이 다르면 분리
- 향후 발전 방향이 다르면 분리

### 2. Context의 적절한 사용

**Context가 적합한 경우:**
- Props Drilling이 3단계 이상
- 상태가 자주 변경되지 않음
- 공유 범위가 명확함

**Context를 피해야 하는 경우:**
- 성능이 중요한 상태 (→ Zustand, Jotai 사용)
- 전역 상태 (→ Redux 등 전역 상태 관리 라이브러리)

### 3. React Query의 진가

**단순 데이터 페칭 이상의 가치:**
- 캐싱으로 네트워크 요청 절감
- Optimistic Update로 UX 향상
- 에러 처리 및 재시도 자동화
- 윈도우 포커스/재연결 시 자동 갱신

## 개선 방안

### 단기 개선 (1-2주)

1. **키보드 단축키 지원**
   - `Ctrl+S`: 저장
   - `Esc`: 모달 닫기
   - `Tab`: Todo 항목 간 이동

2. **드래그 앤 드롭**
   - Todo 순서 변경 (react-beautiful-dnd)

3. **자동 저장**
   - 3초 디바운스로 자동 저장
   - "Saving..." 인디케이터 표시

### 중기 개선 (1-2개월)

1. **오프라인 지원**
   - Service Worker로 오프라인 모드 구현
   - 온라인 복귀 시 자동 동기화

2. **협업 기능**
   - WebSocket으로 실시간 동기화
   - 다른 사용자 수정 사항 알림

3. **반복 Todo**
   - "매일", "매주" 등 반복 설정
   - 템플릿 기능

## 결론

Todo 앱의 생성/수정 모달은 단순해 보이지만, **확장 가능한 설계**를 위해 여러 아키텍처 패턴을 적용했습니다:

1. **컴포넌트 분리**: 생성/수정 모달을 독립적으로 관리하면서 UI 재사용
2. **Context 활용**: Props Drilling 없이 날짜 상태 공유
3. **Compound Component**: 공통 UI를 논리적으로 그룹화
4. **React Query**: 효율적인 캐싱 및 Optimistic Update

이러한 설계는 초기 구현 시간을 조금 늘렸지만, **새 기능 추가 시 변경 범위를 최소화**하여 장기적인 유지보수 비용을 크게 절감했습니다. 특히 카테고리 기능 추가 예시에서 볼 수 있듯이, 기존 코드를 거의 건드리지 않고 확장할 수 있었습니다.

프로젝트를 통해 배운 가장 중요한 교훈은 **"지금 당장의 편리함보다 미래의 확장성"**을 우선시하는 것입니다. 작은 프로젝트라도 견고한 아키텍처는 개발 경험을 크게 향상시킵니다.
